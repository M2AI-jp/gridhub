# マスメ ルールブック（rules 1）

> 5mm方眼ノートに描いたすごろくで、ソフトウェア開発を進めるゲーム。
> Linear や Jira の「文字だけのタスク」に、**盤面・駒・セーブデータ**という「状態」を持たせる。

小学生のころ、方眼ノートにマス目を引いて、すごろく兼RPGを作って兄弟で遊んだ。
マスメはそれを開発に持ち込む。人間も LLM エージェントも、同じ盤面を見て「いまどこにいて、次に何をして、どこで合流するか」を共有する。

---

## 0. なぜゲームにするのか

LLM エージェントに開発を任せると、だいたい次のことが起きる。

| 起きること | マスメのルール |
| --- | --- |
| コンテキストが切れると、どこまでやったか分からなくなる | 進捗は**冒険の書**（追記専用のセーブデータ）にだけ記録される。`masume brief` を読めば誰でも再開できる |
| 「できました」と言うが、実は動いていない | 進めるのは**判定（E2E）に通ったときだけ**。自己申告では1マスも進めない |
| テストを書き換えて通してしまう | 判定ファイルは GM が**封印**する。改変すると「封印が破れている」と記録され、判定できない |
| 頼んでいない所まで手を出して全体を壊す | 見えるのは**視界**の範囲だけ（霧）。触ってよいのは**縄張り**だけ |
| 後から別の変更で、前にできたことが壊れる | 判定は**累積**。宿屋（セーブポイント）以降のマスの判定を毎回まとめて再実行する |
| モジュールを結合したら動かない | 道は一本道ではない。要所に**結合ゲート（ボス戦）**があり、仲間が全員そろってから結合E2Eで戦う |
| セーブデータ自体が壊れる・食い違う | 冒険の書は**ハッシュの鎖**。1文字でも改ざんされると「呪われています」と検出され、修復・ロードできる |
| いまの状態を短く伝えられない | **ふっかつのじゅもん**（12文字）で「その時点の盤面」を一意に指せる |

Git/GitHub はコードの履歴を守る。マスメは**「誰が・どこまで・何を検証済みか」という進行の履歴**を守る。

## 1. 登場するもの

| ゲーム | 開発での意味 | Linear でいうと |
| --- | --- | --- |
| **冒険（クエスト）** | 作りたいプロダクト全体 | Project |
| **地図**（`*.map.json`） | 開発ロードマップ全体。GM が作る | Project の issue 群と依存関係 |
| **キャラクター（駒）** | 完成させるべき**モジュール1つ**を担当するエージェント（または人間） | Assignee |
| **道** | そのキャラクターが通る一方通行のマスの列（`path`） | Assignee ごとの issue の並び |
| **マス（task）** | 1つのタスク。1回のコンテキストで終わる大きさ | Issue |
| **結合ゲート（gate）** | 複数の道が合流する、結合E2Eテストのマス。ボス戦 | Milestone |
| **宿屋（camp）** | セーブポイント。失敗してもここより前には戻らない | Cycle の区切り |
| **あがり（goal）** | 全員が合流する最後の結合ゲート。完成 | Project 完了 |
| **GM** | 地図を描き、判定（E2E）を書いて封印する人。実装はしない | PM / テックリード |
| **勇者（人間）** | 人間にしかできないマス（契約・鍵・決済・承認）を**ハンコ**で進める | 人間の Assignee |
| **冒険の書**（`.masume/`） | セーブデータ。追記専用のイベントログ | Issue の履歴 |

盤面は 5mm 方眼ノートとして描かれる。マスは 4×4 目（2cm角）、道は蛍光ペン、判定に通ったマスには赤ペンの**はなまる**、巻き戻されたマスには**消しゴムの跡**が残る。

---

## 2. 1ターンの流れ（キャラクター）

1. **指令書を読む** — `masume brief <自分のID>`
   いまのマス・判定コマンド・視界に入っている先のマス・仲間の位置・前の自分の日誌・ふっかつのじゅもん が出る。
2. **実装する** — 現在のマスの内容だけ。縄張りの中だけ。
3. **素振り** — 判定コマンドを自分で何度走らせてもよい（記録されない）。
4. **宣言判定** — `masume check <自分のID>`。これが公式の判定で、冒険の書に記録される。
5. **日誌** — `masume note <自分のID> "次の自分への申し送り"`（任意だが強く推奨）。

> 素振りは自由、宣言は一発勝負。TRPG で「判定します」と宣言してからダイスを振るのと同じ。

---

## 3. 判定

- 判定はすべて**コマンド**（E2Eテスト）で行う。終了コード 0 なら成功。
  例外は人間のマス（`stamp`）で、これは人間のハンコで成功になる。
- 判定コマンドは地図に書かれ、地図は冒険の書に**ハッシュ付きで凍結**される。キャラクターは変えられない。
- 判定が参照するファイル（`check.seal`）は GM が**封印**する（ハッシュを記録）。
  - 封印前のマスは判定できない（`未封印` → GM に依頼）。
  - 封印後にファイルが変わっていたら判定できない（`封印が破れています` が記録される）。GM が再封印するか、元に戻す。
- **累積判定**: 宣言判定では、直近のセーブポイント（宿屋・突破済みゲート・ふりだし）より後の、自分の道のマスの判定を**古い順にすべて**走らせる。どれか1つでも落ちたら失敗。
  - 「前にできていたことを壊していない」ことまで含めて、はじめて1マス進める。

## 4. 成功・経験値・レベル・視界

- 成功すると 1 マス進み、そのマスの経験値（task 1 / gate 3 / camp 0）を得る。
- 経験値が `レベル + 1` に達するとレベルアップ（余りは繰り越し）。最大 Lv9。
- **視界** = `min(レベル − 1, 4)` マス先まで。Lv1 は現在のマスしか見えない。
  - 指令書には視界の外のマスのタイトルは**出ない**（霧）。
  - 信頼は実績で増える。失敗すると視界が狭まり、小さく確実に進むことを強いられる。
- 宿屋に着くと自動で休んで（判定なし）通過し、そこがセーブポイントになる。

## 5. 失敗・レベルダウン・巻き戻し

宣言判定に失敗すると:

1. **レベル −1**（最低 Lv1）、経験値は 0 に。
2. **所定の位置まで戻される**。所定の位置は、落ちたマスの `rollback_to` で決まる。
   - `@camp`（既定）… 直近のセーブポイントの次のマス
   - `@here` … 落ちたマスそのもの
   - マスID … 同じ道の、それより前のマス
   - ただし**セーブポイントより前には戻らない**。
3. 戻った位置から失敗地点までに通過していたマスは**消しゴムで消される**（`stale`：要再検証）。
4. 消されたマスは、もう一度判定に通れば元に戻る。ただし**経験値は入らない**。

> 巻き戻されるのは「コード」ではなく「できた、という主張」。コードが正しければ再判定はすぐ通る。正しくなければ、どこで壊れたかが盤面に出る。

## 6. 結合ゲート（合流・ボス戦・解散）

- ゲートは複数の道に同じIDで現れるマス。そこを通る全キャラクターが**メンバー**。
  - 例外: キャラクターが1人だけの冒険では、**あがり**のゲートだけはその1人で戦う（ほかのゲートは置けない）。
- ゲートに着いたキャラクターは**待機**する。
- メンバー全員がそろうと、そろえた最後の判定（またはハンコ）の直後に**自動でボス戦**（ゲートの判定）が始まる（`--no-boss` で保留、あとで `masume check <gateId>`）。
- **勝利**: 全員が経験値 3 を得て、ゲートの次のマスへ進む（**解散**）。ゲートは全員のセーブポイントになる。
- **敗北**: 判定の出力に `MASUME_BLAME: <id>,<id>` 行があれば、そのキャラクターだけが責任を負う（**差し戻し**）。無ければメンバー全員（**全滅**）。
  - 責任を負ったキャラクターはレベル −1、直近のセーブポイントの次まで戻り、その間のマスは消しゴムで消される。
  - 責任のないキャラクターはゲートで待ち続ける。
- ゲートの判定は「そのゲートの結合E2E」だけを走らせる。

## 7. 人間のマス（ハンコ）

- `check.kind: "stamp"` のマスは、指定された人間（`by`）の**ハンコ**で成功になる。
  - `masume stamp <nodeId> --as <humanId>` または盤面の「ハンコを押す」ボタン。
- 人間のマスは、アカウント作成・契約・支払い・本番鍵・デザイン承認など、人間にしかできない／人間が決めるべきことに使う。
- ハンコで最後のメンバーがゲートにそろえば、そのままボス戦が始まる。

## 8. セーブデータ（冒険の書）

- `.masume/log.jsonl` に**追記だけ**される。1行1イベント。各行は前の行のハッシュを含む（ハッシュの鎖）。
- 盤面の状態は、イベントを最初から再生して毎回つくり直す（状態ファイルはただのキャッシュ）。
- `masume verify` で鎖・地図・判定ログの改ざんを検出する。壊れていたら「呪われています（seq N）」。
- `masume repair` で、壊れた所から後ろを退避して鎖を直す。
- **ふっかつのじゅもん**: 最新イベントのハッシュから作る 12 文字のひらがな（例: `ゆうて いみや おうき むこう`）。
  - コミットメッセージ・PR・Linear のコメント・日誌に書いておけば、「その時点の盤面」を一意に指せる。
  - `masume verify --jumon "..."` で、その状態が冒険の書に実在するか確かめられる。
  - `masume load "..."` でその時点の状態に戻せる（戻したこと自体も記録される）。
- 書き込みはロックで1人ずつ。判定中に盤面が動いたら、その判定は無効（もう一度）。

## 9. 地図の改訂

- 計画は変わる。`masume amend <新しい地図>` で地図を改訂できる。
- ただし**歴史は書き換えられない**: すでに通過したマスを消したり、判定を変えたり、その前に新しいマスを差し込んだりはできない。
  タイトル・説明・ラベル・見積もりの修正だけは許される。
- 新しいキャラクター（新しいモジュール）を途中から加えるのは自由。

## 10. 状態と Linear のステータス

| マスの状態 | 盤面の見え方 | Linear |
| --- | --- | --- |
| `fog` 霧 | 鉛筆の下書き | Backlog |
| `open` 視界の中 | ボールペン | Todo |
| `current` 駒がいる | 蛍光ペンで塗られ、駒が立つ | In Progress |
| `waiting` / `ready` ゲートで待機 | 「待機中 2/3」 | In Review |
| `cleared` 突破 | 赤ペンのはなまる | Done |
| `stale` 消された | 消しゴムの跡 | Todo（要再検証） |

`masume export linear` で Linear 形式（CSV/JSON）に書き出せる。`masume import linear` で既存の Linear CSV から地図の下書きを作れる。

---

## 11. 役割の分離（いちばん大事なルール）

- **GM** は地図を描き、判定を書いて封印する。**実装しない。**
- **キャラクター**は実装する。**判定を書かない・変えない。**
- **人間（勇者）**は、人間にしかできないマスと、最後の「あがり」の手前でハンコを押す。

この分離があるから、エージェントの「できました」がそのまま信用できる。

詳しい仕様: [SAVE_FORMAT.md](SAVE_FORMAT.md)（セーブデータ） / [CONTRACTS.md](CONTRACTS.md)（地図・CLI・API） / [GM_GUIDE.md](GM_GUIDE.md)（「xxxのようなアプリを作りたい」から地図を作る手順）
