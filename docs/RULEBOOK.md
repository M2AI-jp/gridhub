# GridHub ルールブック（rules 1）

> **テスト1件が1マス。** 5mm方眼ノートに描いたすごろく（JRPG）で、ソフトウェア開発を進めるゲーム。旧名マスメ。
> Linear や Jira の「文字だけのタスク」に、**盤面・駒・セーブデータ**という「状態」を持たせる。
> 遊び方を決めた考え方は [GAME_DESIGN.md](GAME_DESIGN.md)。

小学生のころ、方眼ノートにマス目を引いて、すごろく兼RPGを作って遊んだ。
GridHub はそれを開発に持ち込む。人間も LLM エージェントも、同じ盤面を見て「いまどこにいて、次に何をして、どこで合流するか」を共有する。

**意味のないマスはない。** 道の上のマスは、どれも本当の作業（テスト1件）か、本当の出来事（判定・セーブ・結合・承認）。
**うまく遊ぶことが、よい開発になる。** 小さく進む・テストを先に・こまめにセーブ・早く結合する、がいちばん強い遊び方。

---

## 0. なぜゲームにするのか

LLM エージェントに開発を任せると、だいたい次のことが起きる。

| 起きること | GridHub のルール |
| --- | --- |
| コンテキストが切れると、どこまでやったか分からなくなる | 進捗は**冒険の書**（追記専用のセーブデータ）にだけ記録される。`gridhub brief` を読めば誰でも再開できる（**伝承**: 次の代が先代の技と日誌を受け継ぐ） |
| 「できました」と言うが、実は動いていない | 進めるのは**判定（テスト）に通ったときだけ**。自己申告では1マスも進めない |
| 一度に大きく変えて、どこで壊れたか分からない | マスは**テスト1件**。いちばん手前の落ちているテストだけを通し、`gridhub step` で確かめて1マスずつ進む |
| テストを書き換えて通してしまう | 判定ファイルは GM が**封印**する。改変すると「封印が破れています」（罠）と記録され、判定できない |
| 頼んでいない所まで手を出して全体を壊す | 見えるのは**視界**の範囲だけ（霧）。触ってよいのは**縄張り**だけ |
| 後から別の変更で、前にできたことが壊れる | 宣言は**累積判定**。前に倒したテストが落ちると、モンスターが**復活**して見える（リグレッション） |
| 失敗したときに戻る場所が無い | **町 = セーブ = Git のコミット**。負けたら町のコミットに戻ってやり直す（戻す前の変更は墓 = git stash に残る） |
| モジュールを結合したら動かない | 要所に**中ボス（結合テスト）**。仲間が全員そろってから結合テストで戦う |
| セーブデータ自体が壊れる・食い違う | 冒険の書は**ハッシュの鎖**。1文字でも改ざんされると「呪われています」と検出され、修復・ロードできる |
| いまの状態を短く伝えられない | **ふっかつのじゅもん**（12文字）で「その時点の盤面」を一意に指せる |

Git/GitHub はコードの履歴を守る。GridHub は**「誰が・どこまで・何を検証済みか」という進行の履歴**を守り、その節目（町）を Git のコミットにする。

## 1. 登場するもの（開発の言葉 ↔ ゲームの言葉）

| 開発 | ゲーム | 地図のデータ | Linear でいうと |
| --- | --- | --- | --- |
| プロダクト全体 | **世界**（冒険） | `quest` | Project |
| 章・リリース | **大陸**（地図の版） | `amend` | — |
| モジュールの担当（エージェントか人間） | **キャラクター**（駒） | `characters[]` | Assignee |
| 担当の作業の並び | **道**（章ごとに分かれ、結合で合流する） | `path` | Assignee ごとの issue の並び |
| **テスト1件**（1つの変数・状態・分岐に対する小さな作業） | **普通のマス = 雑魚モンスター** | `check.cases[]` | issue のチェックリスト |
| タスク（エージェント1回分の仕事） | **ダンジョン**（出口 = 宣言判定） | `task` | Issue |
| セーブ（Git のコミット） | **町**（宿屋） | `camp` | Cycle の区切り |
| 結合テスト（モジュールが初めてつながる所） | **中ボスの砦** | `gate` | Milestone |
| 章のあがりの結合 E2E | **魔王の城** | `quest.goal` | Project 完了 |
| 人間の判断（契約・鍵・承認） | **王様の城**（ハンコ） | `check.kind: "stamp"` | 人間の Assignee |
| 地図と判定を書く人（実装しない） | **GM** | — | PM / テックリード |
| セーブデータ（`.masume/`） | **冒険の書** | — | Issue の履歴 |

山・森・湖・海・町並みの絵は**景色**で、マスではない（ページの空きを埋めるだけ）。

盤面は縦の B5 の 5mm 方眼ノート。すべてが方眼の線に合っている。キャラクターごとの色の道が、ページの上から下へ景色のあいだを曲がりながら下り、結合テストで合流し、また分かれる。見開きで開き、駒が次のページへ進むとノートがめくれる。

## 2. 遊びのループ（入れ子）

1. **1マス（数分）**: いちばん手前の、まだ倒していないモンスター（落ちているテスト1件）を見る → その1つの変数だけを変える → `gridhub step <ID>` で歩く → 倒せば1マス進む。
2. **ダンジョン（エージェント1回分）**: 全部のマスを倒したら、出口で**宣言**（`gridhub check <ID>`）。累積判定なので、前に倒したモンスターの復活も確かめる。
3. **地方（数時間）**: ダンジョン → 町でセーブ → …… → 中ボス戦（仲間がそろって結合テスト）。
4. **大陸（数日）**: 地方 → 王様の城（人間の承認）→ 魔王の城（あがり）→ エンディング → 国境を越えて次の章へ。
5. **積み上げ（ずっと）**: レベル（信頼と視界）・代（伝承）・技（閃き）・守り（倒したテスト）・メダル・宝・モンスター図鑑。

### 1ターンの流れ（キャラクター）

1. **指令書を読む** — `gridhub brief <自分のID>`
   いまのマスとテスト1件ずつの成否・いま戦うテスト・判定コマンド・視界に入っている先・仲間の位置・**先代から受け継いだ技と日誌**・ふっかつのじゅもん が出る。
2. **1マス進める** — いちばん手前の落ちているテストだけを通す。縄張りの中だけ。
3. **歩く** — `gridhub step <自分のID>`。今のダンジョンの判定だけを走らせ、テスト1件ずつの成否を記録する。**何度でも、罰なし**。
4. **宣言** — 全部のマスを倒したら `gridhub check <自分のID>`。公式の判定（一発勝負）。
5. **日誌** — `gridhub note <自分のID> "次の自分への申し送り"`（強敵を倒した直後の日誌は**技**になる）。

> 歩くのは自由、宣言は一発勝負。TRPG で「判定します」と宣言してからダイスを振るのと同じ。

## 3. 判定

- 判定はすべて**コマンド**（テスト）で行う。終了コード 0 なら成功。例外は人間のマス（`stamp`）で、人間のハンコで成功になる。
- 判定コマンドは地図に書かれ、地図は冒険の書に**ハッシュ付きで凍結**される。キャラクターは変えられない。
- 判定が参照するファイル（`check.seal`）は GM が**封印**する（ハッシュを記録）。
  - 封印前のマスは判定できない（`未封印` → GM に依頼）。
  - 封印後にファイルが変わっていたら判定できない（`封印が破れています` = **罠**が記録される）。GM が再封印するか、元に戻す。
- **テスト1件ずつ**: 判定の出力（`node --test` の `✔`/`✖`、TAP の `ok`/`not ok`、`PASS`/`FAIL` など）から、テスト1件ずつの成否を読む。地図の `check.cases` の名前と結びつける。`cases` が無ければ、出力に出てきたテストがマスになる（まだ走らせていなければ「？」のマスが1つ）。
- **累積判定**: 宣言では、直近のセーブポイント（町・突破済みの中ボス・ふりだし）より後の、自分の道のダンジョンの判定を**古い順にすべて**走らせる。どれか1つでも落ちたら失敗。
  - 「前にできていたことを壊していない」ことまで含めて、はじめてダンジョンを抜けられる。

## 4. 歩く・成功・経験値・レベル・視界

- **歩く**（`step`）は、今のダンジョンの判定だけを走らせて、テスト1件ずつの成否を `stepped` として記録する。**位置もレベルも変わらない**（普通の戦い）。駒は「最初に落ちているマス」に立ち、全部通っていれば出口の前に立つ。
- **宣言が成功**するとダンジョンを抜けて（赤ペンのはなまる）次へ進み、経験値（task 1 / gate 3 / camp 0）を得る。
- 経験値が `レベル + 1` に達するとレベルアップ（余りは繰り越し）。最大 Lv9。
- **視界** = `min(レベル − 1, 4)` マス先まで。Lv1 は現在のダンジョンしか見えない。
  - 指令書には視界の外のマスのタイトルは**出ない**（霧）。
  - 信頼は実績で増える。失敗すると視界が狭まり、小さく確実に進むことを強いられる。

## 5. 宣言の失敗（全滅）・レベルダウン・巻き戻し

宣言に失敗すると:

1. **レベル −1**（最低 Lv1）、経験値は 0 に。
2. **所定の位置まで戻される**。所定の位置は、落ちたマスの `rollback_to` で決まる。
   - `@camp`（既定）… 直近のセーブポイント（町）の次のダンジョン
   - `@here` … 落ちたダンジョンそのもの
   - マスID … 同じ道の、それより前のダンジョン
   - ただし**セーブポイントより前には戻らない**。
3. 戻った位置から失敗地点までに抜けていたダンジョンは**消しゴムで消される**（`stale`：要再検証）。もう一度判定に通れば元に戻る。ただし**経験値は入らない**。
4. **Git でセーブする冒険**（`quest.save: "git"`）では、縄張りのファイルも**町のコミットに戻る**。戻す前の変更は `git stash` に**墓**として残る（指令書に `git stash apply <sha>` が出る）。

> 巻き戻されるのは「できた、という主張」と、町より後の変更。町が近ければ失うものは小さい。だから、こまめにセーブ（町）する地図が強い。

## 6. 町（セーブ）

- 町（camp）に着くと宿屋に泊まって（判定なし）通過し、そこがセーブポイントになる。突破した中ボスの砦もセーブポイント。
- **Git でセーブする冒険**では、町に着くと、エンジンが**そのキャラクターの縄張りの変更だけをコミット**する（push はしない。ほかの人の変更やステージには触れない）。中ボスを突破したときは、メンバー全員の縄張りを1つのコミットに。コミットのハッシュは `saved` として冒険の書に残り、盤面の町の看板に `commit a1b2c3d` と書かれる。
- `gridhub quest` で生まれる冒険は、既定で Git でセーブする（`quest.save: "git"`）。`quest.save` の無い地図では Git に触らない（町はセーブポイントの意味だけ）。

## 7. 中ボス（結合テスト）・魔王（あがり）

- 中ボスの砦（gate）は、複数の道に同じIDで現れるマス。そこを通る全キャラクターが**メンバー**。
  - 例外: キャラクターが1人だけの冒険では、**あがり**だけはその1人で戦う（ほかのゲートは置けない）。
- 砦に着いたキャラクターは**待機**する。メンバー全員がそろうと、そろえた最後の判定（またはハンコ）の直後に**自動でボス戦**（連携）が始まる（`--no-boss` で保留、あとで `gridhub check <gateId>`）。
- ボスの HP は、その結合テストのテスト件数。
- **勝利**: 全員が経験値 3 を得て、砦の次へ進む（**解散**）。砦は全員のセーブポイントになる（Git でセーブする冒険ではコミットも）。
- **敗北**: 判定の出力に `MASUME_BLAME: <id>,<id>` 行があれば、そのキャラクターだけが責任を負う（**差し戻し**）。無ければメンバー全員（**全滅**）。
  - 責任を負ったキャラクターはレベル −1、直近のセーブポイント（町）の次まで戻り、その間のダンジョンは消しゴムで消される（Git でセーブする冒険では、縄張りのファイルも町のコミットに戻る）。
  - 責任のないキャラクターは砦で待ち続ける。
- 魔王の城（`quest.goal`）は全員で戦う最後の結合。勝つと**エンディング**（その章の記録から作る文）が流れ、国境が開く（次の章）。

## 8. 人間のマス（王様の城・ハンコ）

- `check.kind: "stamp"` のマスは、指定された人間（`by`）の**ハンコ**で成功になる。
  - `gridhub stamp <nodeId> --as <humanId>` または盤面の「ハンコを押す」ボタン。
- 人間のマスは、アカウント作成・契約・支払い・本番鍵・デザイン承認など、人間にしかできない／人間が決めるべきことだけに使う。あがりの手前には必ず1つ。
- ハンコで最後のメンバーが砦にそろえば、そのままボス戦が始まる。

## 9. 積み上げ（ずっと残るもの）

| もの | 開発の意味 | どう増えるか |
| --- | --- | --- |
| レベル・視界 | 信頼 | 宣言の成功で経験値。失敗で −1 |
| **代**（伝承） | エージェントの出撃1回 = 1代 | 出撃（`sortie`）のたびに。盤面に「書記 3代目」 |
| **技**（閃き） | 苦労して分かったこと | 何度も負けたテスト（**強敵**）をついに倒した直後の日誌。次の代の指令書に必ず出る |
| 守り | 倒したテスト | 以後の宣言のたびに一緒に戦う（累積判定）。壊れたら**復活**して見える |
| ちいさなメダル | 全部通してから出した | ダンジョンの出口を一発で抜けた数 |
| 宝 | 判定のバグを見つけて報告した | GM がそのキャラクターのいるダンジョンの判定を直して封印し直した数 |
| 罠 | 判定ファイルを書き換えた | 封印破りの数 |
| **モンスター図鑑** | 計画したテストの達成 | 冒険のすべてのテストのうち、いま通っているものの数 |

## 10. 作戦（人間がエージェントに出す方針）

`gridhub party --tactic <作戦>`（`.masume/party.json` の `tactic`、盤面の出撃の窓でも）。作戦はルールを変えない。変わるのは、エージェントの動き方と1回の出撃の長さ（利用料）。

| 作戦 | 動き方 | 止まる所 |
| --- | --- | --- |
| いのちだいじに（`careful`） | 1マスずつ `step` で確かめる。全部通るまで宣言しない | ダンジョンを1つ抜けたら |
| バッチリがんばれ（`balanced`、既定） | 小さく変えて `step` を回す。全部通ったら宣言 | ダンジョンを1つ抜けたら |
| ガンガンいこうぜ（`bold`） | 次の町まで、ダンジョンを続けて進む | 町に着いたら（セーブしたら）・砦で待機になったら |

どの作戦でも、宣言に2回失敗したら止まって報告する。

## 11. うまい遊び方が、よい開発になる

| 遊びの判断 | ルールで起きること | 開発で身につくこと |
| --- | --- | --- |
| 歩く（step）は何度でもただ | 普通のマスで負けても罰がない | テストを先に、小さく何度も回す |
| 宣言は一発勝負 | 出口で負けると Lv−1・町からやり直し | 全部通ってから出す（自己申告しない） |
| 一発で出口を抜ける | ちいさなメダル | 通るまで確かめてから出す |
| 町でセーブ | コミットされる。負けてもそこからやり直せる | こまめにコミットする |
| 町から遠く離れる | 負けると、失うもの（町からの変更）が大きい | 大きすぎる変更は危ない |
| 中ボスに負ける | 責任のある仲間だけ、町からやり直し | 結合を早く小さく。契約を守る |
| 強敵を倒して、日誌を書く | 技として残り、次の代に引き継がれる | 苦労して分かったことを書き残す |
| 判定のバグを見つけて報告 | 宝（GM が判定を直して封印し直す） | テストを書き換えずに、報告する |
| 判定ファイルを書き換える | 罠（封印破り）: 判定できない・記録が残る | テストを都合よく変えない |
| 前に通ったテストを壊す | モンスターが**復活**して見える | リグレッションにすぐ気づく |

## 12. セーブデータ（冒険の書）

- `.masume/log.jsonl` に**追記だけ**される。1行1イベント。各行は前の行のハッシュを含む（ハッシュの鎖）。
- 盤面の状態は、イベントを最初から再生して毎回つくり直す（状態ファイルはただのキャッシュ）。テスト1件ずつの成否も、記録された判定の出力から導く。
- `gridhub verify` で鎖・地図・判定ログの改ざんを検出する。壊れていたら「呪われています（seq N）」。
- `gridhub repair` で、壊れた所から後ろを退避して鎖を直す。
- **ふっかつのじゅもん**: 最新イベントのハッシュから作る 12 文字のひらがな（例: `ゆうて いみや おうき むこう`）。
  - コミットメッセージ・PR・Linear のコメント・日誌に書いておけば、「その時点の盤面」を一意に指せる。
  - `gridhub verify --jumon "..."` で、その状態が冒険の書に実在するか確かめられる。
  - `gridhub load "..."` でその時点の状態に戻せる（戻したこと自体も記録される。戦いの記録は巻き戻らない）。
- 書き込みはロックで1人ずつ。判定中に盤面が動いたら、その判定は無効（もう一度）。

## 13. 地図の改訂（国境）

- 計画は変わる。`gridhub amend <新しい地図>` で地図を改訂できる（新しい章 = 新しい大陸）。
- ただし**歴史は書き換えられない**: すでに通過したマスを消したり、判定を変えたり、その前に新しいマスを差し込んだりはできない。
  タイトル・説明・ラベル・見積もりの修正だけは許される。
- 新しいキャラクター（新しいモジュール）を途中から加えるのは自由。

## 14. 状態と Linear のステータス

| マスの状態 | 盤面の見え方 | Linear |
| --- | --- | --- |
| `fog` 霧 | 鉛筆の下書き | Backlog |
| `open` 視界の中 | ボールペン | Todo |
| `current` 駒がいる | 蛍光ペンで塗られ、駒が最初に落ちているテストのマスに立つ | In Progress |
| `waiting` / `ready` 砦で待機 | 「待機 2/3」 | In Review |
| `cleared` 突破 | 赤ペンのはなまる（モンスターには赤い斜線） | Done |
| `stale` 消された | 消しゴムの跡 | Todo（要再検証） |

`gridhub export linear` で Linear 形式（CSV/JSON）に書き出せる（地図に `cases` があれば、テストのチェックリストも）。`gridhub import linear` で既存の Linear CSV から地図の下書きを作れる。

## 15. 役割の分離（いちばん大事なルール）

- **GM** は地図を描き、判定を書いて封印する。**実装しない。**
- **キャラクター**は実装する。**判定を書かない・変えない。**
- **人間（勇者）**は、人間にしかできないマス（王様の城）と、最後の「あがり」の手前でハンコを押し、エージェントに**作戦**を出す。

この分離があるから、エージェントの「できました」がそのまま信用できる。
