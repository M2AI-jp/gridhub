# GridHub ルールブック（rules 1）

> **テスト1件が1マス。** 5mm方眼ノートに描いたすごろくの上で、ソフトウェアづくりを進めるゲームです。旧名マスメ。
> このルールブックは**冒険のことば**（モンスター・ダンジョン・町・ハンコ・全滅）で書いてあります。
> 開発のことば（テスト・タスク・コミット・承認・リグレッション）で読みたい人は、最初の「ことばの対応表」と [README.md](../README.md) をどうぞ。盤面と CLI の字も、右上のボタンか `gridhub words dev` で開発のことばに切り替えられます。

小学生のころ、方眼ノートにマス目を引いて、すごろくとロールプレイングを混ぜた遊びを作ったことはありませんか。
GridHub はそれを、ソフトウェアづくりに持ち込みます。人間も AI のキャラクターも、同じ盤面を見て「いまどこにいて、次に何をして、どこで仲間と合流するか」を分かち合います。

**意味のないマスはありません。** 道の上のマスは、どれも本当の仕事（テスト1件）か、本当の出来事（判定・セーブ・合流・承認）です。
**うまく遊ぶことが、よい仕事になります。** 小さく進む・先に試す・こまめにセーブする・早く合流する。それがいちばん強い遊び方になるように、ルールを組んであります。

## ことばの対応表

冒険のことばが、開発では何にあたるかの一覧です。本文では冒険のことばだけを使い、開発のことばはこの表にまとめます。

| --- | --- | --- |

| 強敵・技 | 2回以上負けたテストと、それを通した直後のメモ（引き継ぎ） | — |
| ちいさなメダル | 最初の判定で合格 | — |
| 宝箱 | テストの不具合を見つけて報告し、直された | — |
| 罠 | テストのファイルを書き換えた | — |

| 封印 | テストのファイルのハッシュを記録する（`gridhub seal`） | `check.seal` |

| 墓 | `git stash` | — |

| 瓦版 | ニュース | `quest.news` |

山・森・湖・海・町並みの絵は**景色**で、マスではありません（ページの空きを埋めるだけです）。

## 0. なぜゲームにするのか

AI のキャラクターに仕事を任せると、だいたい次のことが起きます。GridHub のルールは、その1つ1つに答えています。

| 起きること | GridHub のルール |
| --- | --- |
| 途中で記憶が切れて、どこまでやったか分からなくなる | 進み具合は**冒険の書**にだけ記録されます。指令書を読めば、だれでも続きから再開できます（**伝承**: 次の代が先代の技と日誌を受け継ぐ） |
| 「できました」と言うけれど、実は動いていない | 進めるのは**宣言判定に通ったときだけ**。自己申告では1マスも進めません |
| 一度に大きく変えて、どこで壊れたか分からない | マスは**テスト1件**。いちばん手前のモンスターだけを倒し、歩いて確かめて、1マスずつ進みます |
| テストを書き換えて通してしまう | 判定のファイルは GM が**封印**します。書き換えると「封印が破れています」（罠）と記録され、判定できません |
| 頼んでいない所まで手を出して全体を壊す | 見えるのは**視界**の中だけ（霧）。触ってよいのは**縄張り**だけです |
| あとの変更で、前にできたことが壊れる | 宣言判定は**累積**です。前に倒したモンスターが落ちると、**復活**して盤面に見えます |
| 失敗したときに戻る場所が無い | **町でセーブ**します。負けたら町からやり直し（戻す前の変更は墓に残ります） |
| 部品をつないだら動かない | 要所に**中ボスの砦**。仲間が全員そろってからボス戦です |
| セーブデータそのものが壊れる・食い違う | 冒険の書は**ハッシュの鎖**。1文字でも書き換えられると「呪われています」と分かり、直せます |
| いまの状態を短く伝えられない | **記録の番号**（seq）とセーブの印（commit）で「その時点」を指せます。`gridhub load` でその時点に戻れます |

Git と GitHub はコードの歴史を守ります。GridHub は**「だれが・どこまで・何を確かめ済みか」という進み具合の歴史**を守り、その節目（町）をセーブにします。

## 1. 盤面と登場するもの

盤面は縦の B5 の 5mm 方眼ノートです。すべてが方眼の線に合っています。キャラクターごとの色の道が、ページの上から下へ、景色のあいだを曲がりながら下り、中ボスの砦で合流し、また分かれます。見開きで開き、駒が次のページへ進むとノートがめくれます。

- **キャラクター**は、作るものの部品を1つずつ受け持ちます。AI のキャラクターと、人間のキャラクター（勇者）がいます。
- **道**はキャラクターごとに1本。道の上に、モンスターのマス・ダンジョンの出口・町・砦・城が並びます。
- **ダンジョン**は、キャラクター1回の出撃でやりきる大きさの仕事です。中にモンスター（テスト1件）が2〜6体います。
- **町**は宿屋でセーブする所。**砦**は仲間と合流してボス戦をする所。**王様の城**は人間がハンコを押す所。**魔王の城**は章のあがりです。
- 盤面の右上のボタンで、字を**冒険のことば**と**開発のことば**に切り替えられます（選んだほうは、その冒険の設定と CLI にも効きます）。

## 2. 遊びのループ

1. **1マス（数分）**: いちばん手前の、まだ倒していないモンスターを見る → その1つに効く変更だけをする → 歩いて確かめる → 倒せたら1マス進む。
2. **ダンジョン（出撃1回分）**: モンスターを全部倒したら、出口で**宣言判定**。累積なので、前に倒したモンスターの復活も確かめます。
3. **地方（数時間）**: ダンジョン → 町でセーブ → …… → 中ボスの砦（仲間がそろってボス戦）。
4. **大陸（数日）**: 地方 → 王様の城（人間のハンコ）→ 魔王の城（あがり）→ エンディング → 国境を越えて次の章へ。
5. **積み上げ（ずっと）**: レベル（信頼と視界）・代（伝承）・技（閃き）・守り（倒したモンスター）・メダル・宝箱・モンスター図鑑。

### 1ターンの流れ（キャラクター）

1. **指令書を読む**。いまのダンジョンと、モンスター1体ずつの様子・いま戦うモンスター・視界に入っている先・仲間の位置・先代から受け継いだ技と日誌・いまの記録の番号が書いてあります。
2. **1マス進める**。いちばん手前の、まだ倒せていないモンスターだけを倒します。縄張りの中だけで。
3. **歩く**。いまのダンジョンの判定だけを走らせ、モンスター1体ずつの様子を記録します。**何度でも、罰はありません**。
4. **宣言判定**。モンスターを全部倒したら、出口で宣言します。公式の判定で、一発勝負です。
5. **日誌**。次の自分への申し送りを書きます。強敵を倒した直後の日誌は**技**になります。

> 歩くのは自由、宣言は一発勝負。卓上ゲームで「判定します」と宣言してからダイスを振るのと同じです。

## 3. 判定

- 判定はすべて**判定のファイル**（テスト）で行います。通れば成功です。例外は王様の城で、人間のハンコで成功になります。
- 判定のやり方は地図に書かれ、地図は冒険の書に**ハッシュ付きで凍結**されます。キャラクターは変えられません。
- 判定が読むファイルは GM が**封印**します（ハッシュを記録します）。
  - 封印前のマスは判定できません（「未封印」→ GM に頼みます）。
  - 封印のあとにファイルが変わっていたら判定できません（「封印が破れています」= **罠**が記録されます）。GM が封印し直すか、元に戻します。
- **モンスター1体ずつ**: 判定の出力から、テスト1件ずつの成否を読みます。地図に書かれたモンスターの名前と結びつけます。名前が書かれていない地図では、出力に出てきたテストがモンスターになります（まだ一度も歩いていなければ「？」のマスが1つ）。
- **累積の宣言判定**: 宣言では、直近のセーブポイント（町・突破した砦・ふりだし）より後の、自分の道のダンジョンの判定を**古い順にすべて**走らせます。どれか1つでも落ちたら失敗です。
  - 「前にできていたことを壊していない」ことまで含めて、はじめてダンジョンを抜けられます。

---

## 4. 歩く・レベル・視界

- **歩く**は、いまのダンジョンの判定だけを走らせて、モンスター1体ずつの様子を記録します。**位置もレベルも変わりません**（普通の戦い）。駒は「最初の、まだ倒せていないモンスター」のマスに立ち、全部倒していれば出口の前に立ちます。
- **宣言判定に成功**するとダンジョンを抜けて（赤ペンのはなまる）次へ進み、経験値をもらいます（ダンジョン 1 / 砦 3 / 町 0）。
- 経験値が「レベル + 1」に達するとレベルアップ（余りは繰り越し）。最大 Lv9。
- **視界**は「レベル − 1」マス先まで（最大 4）。Lv1 はいまのダンジョンしか見えません。
  - 指令書には、視界の外のマスの題は**出ません**（霧）。
  - 信頼は実績で増えます。失敗すると視界が狭まり、小さく確実に進むことになります。

---

## 5. 全滅と巻き戻し

宣言判定に失敗すると**全滅**です。

1. **レベル −1**（最低 Lv1）。経験値は 0 に戻ります。
2. **所定の位置まで戻されます**。戻り先は、落ちたマスの `rollback_to` で決まります。
   - `@camp`（既定）… 直近のセーブポイント（町）の次のダンジョン
   - `@here` … 落ちたダンジョンそのもの
   - マスの ID … 同じ道の、それより前のダンジョン
   - ただし**セーブポイントより前には戻りません**。
3. 戻った位置から失敗した所までに抜けていたダンジョンは**消しゴムで消されます**（やり直し）。もう一度判定に通れば元に戻ります。ただし経験値は入りません。
4. **Git でセーブする冒険**では、縄張りのファイルも**町でセーブしたときの中身に戻ります**。戻す前の変更は**墓**に残り、取り出し方が指令書に出ます。

> 巻き戻されるのは「できた、という主張」と、町より後の変更です。町が近ければ失うものは小さい。だから、こまめにセーブする地図が強いのです。

---

## 6. 町（宿屋でセーブ）

- 町に着くと宿屋に泊まって（判定なし）通過し、そこが**セーブポイント**になります。突破した砦もセーブポイントです。
- **Git でセーブする冒険**では、町に着くと、GridHub が**そのキャラクターの縄張りの変更だけをセーブ**します（よその変更には触れません。送りもしません）。砦を突破したときは、メンバー全員の縄張りをまとめて1つのセーブにします。セーブの印は冒険の書に残り、盤面の町の看板に `commit a1b2c3d` と書かれます。
- `gridhub quest` で生まれる冒険は、はじめから Git でセーブします。Git を使わない地図では、町はセーブポイントの意味だけです。

> 仕組み: セーブの正体は Git のコミットです。コミットのメッセージは `gridhub save: <町の名前>`。墓の正体は `git stash` です。くわしくは [README.md](../README.md)「Git のセーブと墓」。

## 7. 中ボスの砦・魔王の城

- **砦**は、複数の道に同じ ID で現れるマスです。そこを通る全キャラクターが**メンバー**です。
  - 例外: キャラクターが1人だけの冒険では、**あがり**だけはその1人で戦います（ほかの砦は置けません）。
- 砦に着いたキャラクターは**待機**します。メンバー全員がそろうと、そろえた最後の判定（またはハンコ）の直後に**自動でボス戦**が始まります（`--no-boss` で保留して、あとで `gridhub check <砦の ID>`）。
- ボスの HP は、その砦のモンスターの数（テストの件数）です。
- **勝利**: 全員が経験値 3 をもらい、砦の次へ進みます（**解散**）。砦は全員のセーブポイントになります（Git でセーブする冒険ではセーブも）。
- **敗北**: 判定の出力に `MASUME_BLAME: <ID>,<ID>` の行があれば、そのキャラクターだけが責任を負います（**差し戻し**）。無ければメンバー全員（**全滅**）。
  - 責任を負ったキャラクターはレベル −1、直近の町の次まで戻り、そのあいだのダンジョンは消しゴムで消されます（Git でセーブする冒険では、縄張りのファイルも町のセーブに戻ります）。
  - 責任のないキャラクターは砦で待ち続けます。
- **魔王の城**は、全員で戦う最後の砦です。勝つと**エンディング**（その章の記録から作る文）が流れ、国境が開きます（次の章）。

---

## 8. 王様の城（ハンコ）

- 王様の城は、指定された人間の**ハンコ**で成功になります。`gridhub stamp <マス> --as <人間の ID>` か、盤面の「ハンコを押す」ボタンです。
- 王様の城は、アカウント作成・契約・支払い・本番の鍵・デザインの承認など、人間にしかできない／人間が決めるべきことだけに使います。あがりの手前には必ず1つあります。
- ハンコで最後のメンバーが砦にそろえば、そのままボス戦が始まります。

## 9. 積み上げ（ずっと残るもの）

| もの | 意味 | どう増えるか |
| --- | --- | --- |
| レベル・視界 | 信頼 | 宣言判定の成功で経験値。失敗で −1 |
| **代**（伝承） | 出撃1回が1代 | 出撃のたびに。盤面に「書記 3代目」 |
| **技**（閃き） | 苦労して分かったこと | 何度も負けたモンスター（**強敵**）をついに倒した直後の日誌。次の代の指令書に必ず出る |
| 守り | 倒したモンスター | 以後の宣言判定のたびに一緒に戦う（累積）。壊れたら**復活**して見える |
| ちいさなメダル | 一発で出口を抜けた | ダンジョンの出口を一発で抜けた数 |
| 宝箱 | 判定のほころびを見つけて報告した | GM がそのダンジョンの判定を直して封印し直した数 |
| 罠 | 判定のファイルを書き換えた | 封印破りの数 |
| **モンスター図鑑** | 計画したモンスターの達成 | 冒険のすべてのモンスターのうち、いま倒しているものの数 |

## 10. 作戦（人間がキャラクターに出す方針）

`gridhub party --tactic <作戦>`（`.masume/party.json` の `tactic`、盤面の出撃の窓でも）。作戦はルールを変えません。変わるのは、キャラクターの動き方と1回の出撃の長さ（かかる時間と利用料）です。

| 作戦 | 動き方 | 止まる所 |
| --- | --- | --- |
| いのちだいじに（`careful`） | 1マスずつ歩いて確かめる。全部倒すまで宣言しない | ダンジョンを1つ抜けたら |
| バッチリがんばれ（`balanced`、既定） | 小さく直しては歩く。全部倒したら宣言 | ダンジョンを1つ抜けたら |
| ガンガンいこうぜ（`bold`） | 次の町まで、ダンジョンを続けて進む | 町に着いたら（セーブしたら）・砦で待機になったら |

どの作戦でも、宣言判定に2回失敗したら止まって報告します。

## 11. うまい遊び方が、よい仕事になる

| 遊びの判断 | ルールで起きること | 身につくこと |
| --- | --- | --- |
| 歩くのは何度でもただ | モンスターに負けても罰がない | 先に試し、小さく何度も回す |
| 宣言は一発勝負 | 出口で負けると Lv−1・町からやり直し | 全部通してから出す（自己申告しない） |
| 一発で出口を抜ける | ちいさなメダル | 通るまで確かめてから出す |
| 町でセーブ | セーブされる。負けてもそこからやり直せる | こまめにセーブする |
| 町から遠く離れる | 負けると、失うもの（町からの変更）が大きい | 大きすぎる変更は危ない |
| 中ボスに負ける | 責任のある仲間だけ、町からやり直し | 早く小さく合流する。約束を守る |
| 強敵を倒して、日誌を書く | 技として残り、次の代に引き継がれる | 苦労して分かったことを書き残す |
| 判定のほころびを見つけて報告 | 宝箱（GM が判定を直して封印し直す） | 判定を書き換えずに、報告する |
| 判定のファイルを書き換える | 罠（封印破り）: 判定できない・記録が残る | 判定を都合よく変えない |
| 前に倒したモンスターを壊す | モンスターが**復活**して見える | 壊れたことにすぐ気づく |

## 12. 冒険の書

- 冒険の書には**追記だけ**されます。1行が1つの出来事で、各行は前の行の指紋（ハッシュ）を含みます（ハッシュの鎖）。
- 盤面の状態は、出来事を最初から再生して毎回つくり直します。モンスター1体ずつの様子も、記録された判定の出力から導きます。
- `gridhub verify` で、鎖・地図・判定の出力の書き換えを見つけます。壊れていたら「呪われています（seq N）」。
- `gridhub repair` で、壊れた所から後ろを退避して鎖を直します。
- **いまの記録**は、記録の番号（seq）とセーブの印（commit）で言います（例: `記録: seq 42 / Git: commit a1b2c3d`。`status`・`brief`・`new` が出します）。
  - 日誌やコミットメッセージや PR に `seq 42` と書けば、「その時点の盤面」を指せます。
  - `gridhub load <seq>` か `gridhub load <commit>` で、その時点の盤面に戻せます（戻したこと自体も記録されます。戦いの記録は巻き戻りません。コードは Git で戻します）。
- 書き込みは1人ずつ（ロック）。判定中に盤面が動いたら、その判定は無効です（もう一度）。

---

## 13. 地図の改訂（国境）

- 計画は変わります。`gridhub amend <新しい地図>` で地図を改訂できます（新しい章 = 新しい大陸）。
- ただし**歴史は書き換えられません**。すでに通過したマスを消したり、判定を変えたり、その前に新しいマスを差し込んだりはできません。題・説明・ラベル・見積もりの修正だけは許されます。
- 新しいキャラクター（新しい部品）を途中から加えるのは自由です。

---

## 14. 役割の分離（いちばん大事なルール）

- **GM** は地図を描き、判定を書いて封印します。**実装しません。**
- **キャラクター**は実装します。**判定を書きません・変えません。**
- **人間（勇者）**は、王様の城と、最後のあがりの手前でハンコを押し、キャラクターに**作戦**を出します。

この分離があるから、キャラクターの「できました」をそのまま信じられます。

## 15. 道具（コマンド）

盤面の中のボタンでできることは、ターミナルからも同じようにできます。`gridhub <command> --help` でくわしい説明が出ます。

| すること | コマンド |
| --- | --- |
| 指令書を読む | `gridhub brief <自分の ID>` |
| 歩く（何度でも・罰なし） | `gridhub step <自分の ID>` |
| 出口で宣言判定（一発勝負） | `gridhub check <自分の ID>` |
| 日誌を書く | `gridhub note <自分の ID> "申し送り"` |
| ハンコを押す（人間） | `gridhub stamp <マス> --as <人間の ID>` |
| 盤面を開く | `gridhub serve` |
| 願いから冒険をつくる（GM） | `gridhub quest "<願い>"` |
| 仲間を出撃させる | `gridhub party --tactic careful|balanced|bold` |
| 盤面の様子・冒険の書・呪いの確認 | `gridhub status` / `gridhub log` / `gridhub verify` |
| その時点に戻る | `gridhub load <seq か commit>` |
| ことばを切り替える | `gridhub words game|dev`（1回だけなら、どのコマンドにも `--words dev`） |

## 16. 開発のことばで読むには

GridHub のすべての字（盤面・CLI・MCP の道具・生成する AGENTS.md）は、**冒険のことば**と**開発のことば**の2つの言い方を持っています。どちらでも、1つの文の中に2つの言い方を並べることはありません。

- 盤面: 右上の「🗡 冒険のことば」ボタンを押すと「⌨ 開発のことば」になります。選んだほうは、その冒険の設定（`.masume/words.json`）とブラウザに残ります。
- CLI: `gridhub words dev`（この冒険の設定）。1回だけなら `--words dev`、環境変数なら `GRIDHUB_WORDS=dev`。
- 文書: このルールブックは冒険のことば、[README.md](../README.md) は開発のことばで書いてあります。

くわしい仕様: [GAME_DESIGN.md](GAME_DESIGN.md)（ゲームデザイン） / [SAVE_FORMAT.md](SAVE_FORMAT.md)（セーブデータ） / [CONTRACTS.md](CONTRACTS.md)（地図・CLI・API） / [GM_GUIDE.md](GM_GUIDE.md)（「xxxのようなアプリを作りたい」から地図を作る手順）
