# GridHub ゲームデザイン

> 開発のやり方を、そのまま JRPG すごろくのルールにする。
> **意味のないマスはない。** 道の上のマスは、どれも本当の作業か、本当の出来事。
> **うまく遊ぶことが、よい開発になる。** 小さく進む・テストを先に・こまめにセーブ・早く結合する、がいちばん強い遊び方になるようにルールを組む。

山・森・湖・海・町並みの絵は「景色」で、マスではない（その上は歩かない。ページの空きを埋めるだけ）。

---

## 1. 名作から学んだこと（要素ではなく、原理）

参考にした作品: ドラゴンクエスト IV・V・VI、ロマンシング サ・ガ 2・3、ファイナルファンタジー V・VI、聖剣伝説3、クロノ・トリガー。

| 作品 | よさの原理 | GridHub でのルール |
| --- | --- | --- |
| DQ IV・FF VI・ロマサガ3・聖剣伝説3 | **群像劇。** 仲間それぞれの章（DQ IV の1〜4章[^dq4]、FF VI の3つに分かれる物語[^ff6]、ロマサガ3の8人の主人公[^rs3]、聖剣伝説3の主人公ごとに変わる物語[^mana3]）を別々に進め、やがて**導かれて合流する** | キャラクター（モジュール）ごとに自分の道（章）があり、それぞれの順番で進む。結合テスト（中ボス）で合流し、また分かれる。盤面は道ごとに、そのキャラクターの「章」として読める |
| DQ IV | **AI の仲間に、人間が「さくせん」を出す**（ガンガンいこうぜ・いのちだいじに）[^dq4] | 人間はエージェントに**作戦**を出す（§5.7）。作戦で、1回の出撃でどこまで進み、いつ宣言し、いつ止まるかが変わる。人間は指揮、AI は実行 |
| ロマサガ2 | **伝承法。** 皇帝は代替わりしても、先帝の能力と記憶を受け継ぐ[^rs2] | エージェントの1回の出撃が「1代」。コンテキストは切れても、先代の**技と記憶**（技・日誌・指令書）を受け継ぐ（§5.8）。盤面に「書記 3代目」と出る |
| ロマサガ2・3 | **閃き。** 苦戦の中で新しい技を覚え、その勝利が記憶に残る[^saga] | 何度も負けたテストをついに倒すと「強敵を倒した」。その直後の日誌が**技**になり、次の代に必ず伝わる（§5.6） |
| ロマサガ3・FF VI | **自由な順番。** 正解のルートがない[^rs3]。後半は世界が変わり、自分で旅を組み立てる[^ff6] | 道どうしに順番の決まりはない（地図の合流だけが決まり）。章（大陸）が変わると、世界の形も変わる（新しい版の地図） |
| DQ V | **倒した敵が仲間になる**[^dq5] | 一度倒したテストは**守り**になる。以後の宣言のたびに一緒に戦い（累積判定）、後の変更で壊れたら**復活**して見える（リグレッション） |
| DQ VI・FF V | **転職しても、身につけたものは積み上がる**[^dq6][^ff5] | キャラクターの積み上げ（倒したテスト・技・メダル）は章をまたいで残る。次の章（大陸）へ持ち越す |
| クロノ・トリガー | **敵は見えていて、ランダムエンカウントはない。仲間がそろうと連携技。遊び方で結末が変わる**[^ct] | マスのモンスターは地図に書いたテストそのもので、最初から見えている。結合テストはそろうと自動で始まる連携。章のエンディングは記録から毎回違う文になる（§5.9） |
| ドラゴンクエスト（堀井雄二氏の作り方） | **ゴールから作り、始まりをいちばん大事にする。** 苛立つ所は削り、少しだけ苦労する所を意図して置く[^dq-map][^dq-begin] | 1ページ目から章のあがり（魔王の城）が見える。最初の地方はやさしく、緊張（中ボス）と安心（町）を交互に置く（§6） |

## 2. 柱（判断に迷ったら、ここに戻る）

1. **すべてのマスに意味がある。**
2. **本当に起きたことしか起きない。** 盤面の出来事はすべて冒険の書（ハッシュの鎖）から導く。
3. **うまく遊ぶ＝よい開発。** ずるはいつも損をし、よい習慣はいつも得をする。
4. **エンジニアが一目で読める。** 字は技術の言葉が先（`POST /api/memos`、`テスト 3/5`、`commit a1b2c3d`）。ゲームの言葉は添え書き。
5. **人間と LLM が同じ盤面で遊ぶ。** 指令書（brief）は、盤面と同じことを文字で言う。

## 3. 世界の階層（レベルデザインの単位）

| ゲーム | 開発 | 地図のデータ |
| --- | --- | --- |
| **世界** | プロダクト全体 | `quest` |
| **大陸**（ページのかたまり） | 章・リリース | 地図の版（`amend` で増える） |
| **国境** | 章の境目 | `amend` |
| **魔王の城（大ボス）** | 章のあがりの結合 E2E | `quest.goal` のゲート |
| **地方** | マイルストーン（結合と結合のあいだ） | ゲートで区切られた道 |
| **中ボスの砦** | 結合テスト（モジュールが初めてつながる所） | `gate` |
| **ダンジョン** | タスク（エージェント1回分の仕事） | `task` |
| **普通のマス（雑魚モンスター）** | **テスト1件 = 1つの変数（値・状態・分岐）に対する小さな作業1つ** | `check.cases[]` |
| **町（宿屋）** | **セーブ = Git のコミット** | `camp` |
| **王様の城** | 人間の判断（契約・鍵・承認） | `check.kind: "stamp"` |

## 4. マスと遊びのループ

### マスの種類（すべて）

| マス | 開発の意味 | 何が起きるか |
| --- | --- | --- |
| **普通のマス** | テスト1件 | テストが通ると、モンスターを倒して1マス進む。落ちているあいだは、そのマスで戦い続ける（罰はない） |
| **ダンジョンの出口** | タスクの宣言判定（最後の町から今までの累積） | 通ればダンジョンを抜ける（経験値・はなまる）。落ちれば**全滅**: Lv−1、最後の町からやり直し |
| **町** | セーブ（Git のコミット） | 着くと宿屋に泊まる＝その町までの変更をコミットする。ここより前には戻らない |
| **中ボスの砦** | 結合テスト | 仲間がそろうと戦う（連携）。負けると、責任のある仲間は**最後の町からやり直し** |
| **王様の城** | 人間のハンコ | 王様（人間）の許しで進む |
| **魔王の城** | 章のあがり | 全員で戦う。勝つとエンディング、国境が開く（次の章） |

### ループ（入れ子）

1. **1マス（数分）**: いちばん手前の、まだ倒していないモンスター（落ちているテスト1件）を見る → その1つの変数だけを変える → `gridhub step` で歩く → 倒せば1マス進む。
2. **ダンジョン（エージェント1回分）**: 全部のマスを倒したら、出口で**宣言**（`gridhub check`）。累積判定なので、前に倒したモンスターの**復活**も確かめる。
3. **地方（数時間）**: ダンジョン → 町でセーブ → …… → 中ボス戦（仲間がそろって結合テスト）。
4. **大陸（数日）**: 地方 → 王様の城（人間の承認）→ 魔王の城（あがり）→ エンディング → 国境を越えて次の章へ。
5. **積み上げ（ずっと）**: レベル（信頼と視界）・代（伝承）・技（閃き）・守り（倒したテスト）・メダル・宝・モンスター図鑑。

### うまい遊び方が、よい開発になるように

| 遊びの判断 | ルールで起きること | 開発で身につくこと |
| --- | --- | --- |
| 歩く（step）は何度でもただ | 普通のマスで負けても罰がない | テストを先に、小さく何度も回す |
| 宣言は一発勝負 | 出口で負けると Lv−1・町からやり直し | 全部通ってから出す（自己申告しない） |
| 一発で出口を抜ける | ちいさなメダル | 通るまで確かめてから出す |
| 町でセーブ | コミットされる。負けてもそこからやり直せる | こまめにコミットする |
| 町から遠く離れる | 負けると、失うもの（町からの変更）が大きい | 大きすぎる変更は危ない |
| 中ボスに負ける | 責任のある仲間だけ、町からやり直し | 結合を早く小さく。契約を守る |
| 強敵を倒して、日誌を書く | 技（閃き）として残り、次の自分に引き継がれる | 苦労して分かったことを書き残す |
| 判定のバグを見つけて報告 | 宝箱（GM が判定を直して封印し直す） | テストを書き換えずに、報告する |
| 判定ファイルを書き換える | 罠（封印破り）: 判定できない・記録が残る | テストを都合よく変えない |
| 前に通ったテストを壊す | モンスターが**復活**して見える | リグレッションにすぐ気づく |

## 5. ルール（エンジンが決める。冒険の書から導く）

### 5.1 マス（テストケース）
- 地図のタスクの判定に `cases`（テスト名の配列）を書く。1件が1マス。
- 判定の出力から、テスト1件ずつの成否を読む（`node --test` の `✔`/`✖`、TAP の `ok`/`not ok`、`ok 名前`/`PASS`/`FAIL`）。名前で `cases` と結びつける（見つからなければ出てきた順）。
- `cases` が無い地図は、判定の出力に出てきたテストがマスになる。まだ一度も走らせていなければ「？」のマスが1つ（中の分からないダンジョン）。

### 5.2 歩く（`gridhub step <キャラID>`）
- 今のダンジョンの判定だけを走らせて、テストごとの成否を `stepped` として記録する。レベルも位置も変わらない（普通の戦い）。
- 駒は「最初に落ちているマス」に立つ。全部通っていれば出口の前に立つ。
- 一度倒したテストが、後の歩き・宣言で落ちたら**復活**（リグレッション）として数える。
- 同じテストに2回以上負けてから倒したら**強敵を倒した**として数える。

### 5.3 宣言（`gridhub check`。今のルールのまま）
- 町（セーブポイント）から今のダンジョンまでの判定を全部走らせる。通れば出口を抜ける。落ちれば全滅（Lv−1、町の次のダンジョンから。間のはなまるは消しゴム）。
- 宣言の出力も、テストごとの成否として記録する（復活・強敵の数え方は 5.2 と同じ）。

### 5.4 町＝セーブ（Git）
- 地図の `quest.save` が `"git"` の冒険では、町に着くと、エンジンが**そのキャラクターの縄張りの変更をコミット**する（push はしない）。コミットのハッシュを `saved` として冒険の書に残す。`gridhub quest` で生まれる冒険は、既定で `"git"`。
- 宣言や中ボス戦に負けて町に戻されたキャラクターは、縄張りのファイルを**町のコミットに戻してから**やり直す。戻す前の変更は `git stash` に「墓」として残す（なくならない。指令書に取り出し方が出る）。これを `restored` として残す。
- `quest.save` が無い地図では Git に触らない（町はセーブポイントだけの意味。このリポジトリ自身の冒険もこれ）。

### 5.5 中ボス・魔王（今のルールのまま）
- メンバーがそろうと戦う。負けると `MASUME_BLAME` のキャラクター（無ければ全員）が Lv−1、最後の町に戻る（5.4 のとおり、ファイルも町のコミットに戻る）。
- 中ボス・魔王の HP は、その結合テストのテスト件数。

### 5.6 積み上げ
- **レベル**（信頼）と視界は今のまま（task 1 / gate 3、`視界 = min(Lv−1, 4)`）。
- **技（閃き）**: 強敵を倒したあと、次の宣言までに書いた日誌が「技」になる。指令書には、そのキャラクターの技が新しい順に出る（代が替わっても、苦労して分かったことは失われない。§5.8）。
- **ちいさなメダル**: ダンジョンの出口を一発で抜けた数。
- **宝**: GM がそのキャラクターのいるダンジョンの判定を直して封印し直した数（判定のバグを見つけた）。
- **モンスター図鑑**: 冒険のすべてのテストのうち、いま倒している（通っている）ものの数。図鑑を埋めること＝計画したテストを全部通すこと。
- **罠**: 封印破りの数。

### 5.7 作戦（人間がエージェントに出す方針）
- `gridhub party --tactic <作戦>`（`.masume/party.json` の `tactic` でも。盤面の出撃の窓でも選べる）。エージェントへのプロンプトと、止まる条件が変わる。
  - **いのちだいじに**: 1マスずつ `step` で確かめる。全部のマスを倒すまで宣言しない。1つのダンジョンを抜けたら止まる。
  - **バッチリがんばれ**（既定）: 小さく変えて `step` を回す。全部倒したら宣言。1つのダンジョンを抜けたら止まる。
  - **ガンガンいこうぜ**: 次の町まで、ダンジョンを続けて進んでよい（町でセーブしたら止まる）。
- 作戦はルールを変えない（宣言の重さ・セーブは同じ）。変わるのは、エージェントの動き方と1回の出撃の長さ（利用料）。

### 5.8 伝承（代替わり）
- キャラクターへの出撃1回を「1代」と数える（`sortie` の数）。指令書と盤面に「◯代目」と出る。
- 新しい代の指令書には、先代までの**技**（§5.6）と**直近の日誌**が必ず入る。人間の手で進めるキャラクターも同じ。

### 5.9 エンディング
- 章のあがり（魔王の撃破）で、その章の記録から「エンディング」の文をつくる（倒したモンスターの数・一発合格・強敵・復活・宝・技・かかった出撃の回数）。記録が違えば文も違う。

## 6. レベルデザイン（GM が地図を描くときの決まり）

- **ゴールから描く。** 先に魔王の城（あがりの結合 E2E）を1文で書く。盤面の1ページ目から見えるので、始まりから目的が分かる。
- **1マス = 1つの変数に対する小さな作業 + テスト1件。** 名前は、変える値と期待を技術の言葉で（例「`title` が空なら 400 を返す」）。
- **ダンジョン（タスク）は 2〜6 マス。** 7マス以上なら2つに割る。
- **最初の地方はやさしく。** 最初のダンジョンは 1〜2 マス、最初の町は早めに。ここでルールが全部分かるようにする。
- **緊張と安心を交互に。** 町は 2〜3 ダンジョンごとと、中ボスの直前に置く。町の遠い地方は、意図して置く難所。
- **中ボスは、モジュールが初めてつながる所。** 地方の長さは各キャラクター 2〜4 ダンジョン。
- **王様の城（人間の承認）は、人間が決めるべき所だけ。** あがりの手前には必ず1つ。
- **国境（章）を越えたら、新しい大陸の最初に町を置く。**

## 7. 盤面（見せ方）

- 縦の5mm方眼ノート（B5）。キャラクターごとの色の道が、ページの上から下へ、景色のあいだを曲がりながら下りる。結合テストで合流し、また分かれる。
- 道のマスは、テスト1件ずつ。マスにはモンスターと、テストの名前（拡大・詳細で読める）。倒したモンスターには赤い斜線、復活したモンスターは赤い丸。
- ダンジョンの出口は、タスクの題（`POST /api/memos を作る`）・状態・テストの数（`3/5`）を書いた札。抜けたら赤ペンのはなまる。
- 町はコミットのハッシュを書いた宿屋の看板。王様の城はハンコ。中ボス・魔王は城壁の帯。国境は大陸の境目と「第2章」。
- 見開きで開き、ページをめくって進む。駒が次のページへ進んだら、ノートがめくれる。
- 右の欄はエンジニア向け: なかま（道のり・レベル・技・メダル）、冒険の書（ログ）、台帳（Linear のステータス）、モンスター図鑑（テストの一覧と成否）。

## 8. 互換

- CLI は `gridhub`。`masume` は別名として残す。冒険の書のフォルダ `.masume/`、環境変数 `MASUME_*`、MCP の道具名 `masume_*` は変えない。
- `cases` が無い地図、`quest.save` が無い地図は、今までどおり遊べる（5.1・5.4）。
- 冒険の書（ログ）の形は、イベントの種類が増えるだけ（`stepped` `saved` `restored`）。今までの冒険の書は、そのまま `verify` が通る。
