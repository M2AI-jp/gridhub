# おみくじCLIの契約

このファイルは、この冒険のモジュール間の約束のSSoTである。地図は `quest.map.json`、ユーザーの願いは `WISH.md`、GMが補った前提は `ASSUMPTIONS.md` に置く。実装担当は現在のマスで指定された範囲だけを実装し、契約や判定を変更しない。

## 1. 担当、環境、接続

| ID / 名前 | 編集できる縄張り | 外から使う入口 |
| --- | --- | --- |
| `fortune` / 占い師 | `src/fortune/**` | `node src/fortune/main.mjs` |
| `history` / 書記 | `src/history/**` | `node src/history/main.mjs` |
| `cli` / 伝令 | `src/cli/**` | `node src/cli/main.mjs` |

- 地図、`checks/**`、この契約、前提文書、その他の共有ファイルはGMの管理対象であり、どの担当の縄張りにも入らない。
- 実行環境はNode.js 20以上、標準ライブラリのみ、ESM（`.mjs`）、UTF-8、改行LF。`package.json` の追加は不要。
- 伝令は占い師・書記のCLIを子プロセスとして呼ぶ。実行ファイルは `process.execPath`、引数は配列で渡し、シェルを介さない。相手の入口は自身の `import.meta.url` から `../fortune/main.mjs` / `../history/main.mjs` を解決する。利用者のカレントディレクトリからソースを探さない。
- 伝令は子プロセスにカレントディレクトリと `OMIKUJI_HISTORY_FILE` を引き継ぐ。抽選・保存のロジックを伝令に複製せず、両担当の入口を利用する。他担当のファイルは読み取りのみとする。
- 入口は1要求で終了する。成功は終了コード0、stderrは空。JSONを返す入口はstdoutにJSON値1つと末尾LFだけを出す。
- エラーはstdoutを空にし、stderrに `[コード] 理由\n` を1行出す。スタックトレースや成功表示を混ぜない。コードと終了値は以下の各節による。

## 2. データ

運勢の順番は `["大吉", "中吉", "小吉", "吉", "末吉", "凶"]` とする。

- `Advice` は日本語（漢字・ひらがな・カタカナのいずれか）を含む、空白だけでない1〜120 Unicode文字の文字列。CR/LFを含まない。同じ運勢の助言は全コマンド・全プロセスで固定する。
- `Seed` は `null`、または長さ1以上で `--` から始まらない文字列。`null` はseed指定なしを表す。指定文字列をtrim・数値化・Unicode正規化しない。
- `CatalogEntry` は正確に `{fortune: 運勢, advice: Advice}` の2項目。
- `Draw` は正確に `{fortune: 運勢, advice: Advice, seed: Seed}` の3項目。
- `Record` は正確に `{fortune: 運勢, advice: Advice, seed: Seed, drawnAt: string}` の4項目。`drawnAt` は保存処理時点の `new Date().toISOString()` 形式（UTC、ミリ秒付き）。
- JSONのプロパティ順、インデントは自由。追加項目は設けない。履歴ファイルは1レコード1行のJSONとする。

## 3. 占い師の入口

| コマンド | stdout |
| --- | --- |
| `node src/fortune/main.mjs --catalog` | 上記順の6件の `CatalogEntry` 配列 |
| `node src/fortune/main.mjs --seed <文字列>` | `Draw` 1つ |
| `node src/fortune/main.mjs` | `Draw` 1つ（`seed: null`） |

seed付き抽選は、seedのUTF-8をSHA-256でハッシュ化し、先頭4バイトの符号なしビッグエンディアン整数を6で割った余りで運勢を選ぶ。JSONの値は別プロセスでも同じになる。seedを省いた抽選は、例えば `node:crypto` の `randomInt(6)` で等確率に選ぶ。有限回の判定では乱数の偏りを合否条件にしない。

占い師は履歴を読み書きしない。カタログと抽選の助言は一致させる。

未知の引数、値なし/空文字のseed、`--` で始まるseed、重複seed、`--catalog` と他の引数の併用は `[E_USAGE]`、終了コード2。

段階: `F1` はカタログ、`F2` はseed付き抽選、`F3` は通常抽選と不正引数を担当する。

## 4. 書記の入口と履歴

書記は `OMIKUJI_HISTORY_FILE` が空でなければそのパスを使う。未設定または空文字なら `path.resolve(process.cwd(), ".omikuji-history.jsonl")` を使う。環境変数の相対パスはカレントディレクトリから解決する。

| コマンド | stdin | stdout / 効果 |
| --- | --- | --- |
| `node src/history/main.mjs list` | 使用しない | `Record[]`。未作成なら `[]`。ファイルも親ディレクトリも作らない |
| `node src/history/main.mjs append` | JSONの `Draw` 1つ（末尾空白可） | 保存時刻を加えた `Record` を1件追記し、その同じレコードを返す |

- ファイルはUTF-8のJSON Lines。空ファイルは0件として扱う。既存ファイルの最後のLFは省略可だが、途中の空行・不正JSON・不正な `Record` は破損とする。
- `list` はファイル順で返す。読んだファイルの内容を変えない。
- `append` は入力と既存ファイル全体を検証してから必要な親ディレクトリを作り、1件だけ末尾に加える。既存ファイルがLFで終わらない場合は区切りのLFを補う。既存のバイト列を削除・整形・上書きしない。
- 同じseed・同じ結果でも毎回追記する。日時は各保存時点の時刻とし、異なる日時になること自体は要求しない。
- 書記は運勢の名前とレコードの形を検証するが、占い師の助言文と一致するかは問い合わせない。独立して実装できるようにする。
- 読み書きは逐次実行を対象とする。同時実行のロックや異常終了時のトランザクションは今回の範囲外。

| 状況 | コード / 終了値 | 保全条件 |
| --- | --- | --- |
| コマンドがない、不明、余分な引数 | `E_USAGE` / 2 | 書き込まない |
| appendのstdinが不正JSON・不正な `Draw` | `E_RECORD` / 2 | ファイルを作成・変更しない |
| 既存履歴が不正JSON・不正な `Record` | `E_HISTORY_CORRUPT` / 1 | listもappendも元のバイト列を保持する |
| 未作成ファイル以外の読み取りエラー、親が通常ファイル、保存先がディレクトリ等 | `E_HISTORY_IO` / 1 | 成功を返さず、既存の内容を保持する |

段階: `H1` は正常な履歴の一覧、`H2` は追記・保存先、`H3` は不正入力・破損・I/Oエラー時の保全を担当する。

## 5. 伝令の利用者向けCLI

```text
node src/cli/main.mjs [--seed <文字列>] [--json]
node src/cli/main.mjs --history [--json]
node src/cli/main.mjs --help
```

- 各オプションの順番は自由。ただし重複、未知のオプション、位置引数、値なし/空文字/`--` で始まるseedを認めない。`--seed=value` 形式は扱わない。
- `--history` と `--seed` は併用不可。`--help` は単独で使う。不正な組み合わせは `E_USAGE` / 2。解析を完了してから他担当を呼ぶ。
- `--help` は `使い方` と4つのオプション（`--seed`、`--json`、`--history`、`--help`）を説明して終了する。他担当も履歴も不要。
- 通常は占い師を1回呼び、その `Draw` を書記の `append` にJSONで渡し、保存の成功を確認してから表示する。`--seed` は指定時だけ占い師に渡す。
- `--json` の抽選結果は `Draw` だけ。保存日時は履歴から読める。seedが同じならプロセス・表示形式・履歴件数に影響されず同じ抽選結果になる。
- テキストの抽選結果は次の2行。LFで終える。

```text
運勢: <fortune>
ひとこと: <advice>
```

- `--history` は書記の `list` だけを1回呼ぶ。占い師も `append` も呼ばない。`--history --json` は書記の `Record[]` をそのまま返す。
- テキストの履歴は1件1行、`<drawnAt>\t<fortune>\t<advice>\n`（実際のタブ区切り）。見出しや番号は付けない。0件なら `履歴はありません。\n`。
- 子プロセスが契約上のエラーを返したときは、そのエラー行と終了コードを利用者へ伝える。抽選失敗時は保存しない。保存失敗時は抽選成功をstdoutに出さない。
- 子プロセスを起動できない、成功応答が不正JSONなどの接続不良は `E_DEPENDENCY` / 1。各子プロセスのstdoutを利用者のstdoutへ直接流さない。

段階: `C1` はヘルプ・入力検証、`C2` はseed付き抽選・表示・保存の接続、`C3` は通常抽選・履歴表示・依存先の失敗伝達を担当する。

## 6. 判定と結合の順序

- `F1/F2`、`H1/H2`、`C1/C2` は他の担当を待たずに合格できる。伝令の判定は、一時ディレクトリに伝令のコードと固定応答のフェイクを配置し、子プロセスの引数・stdin・呼び出し回数・順序を観測する。テスト用のコードを製品へ追加してはいけない。
- `G1` で初めて3担当の実物を接続し、seed付きのJSON/テキスト抽選と保存内容の一致を検証する。
- 各道は自分の宿屋を通って最後のtaskを行う。`GOAL` は実物の通常抽選、6種類とseedの再現、テキスト/JSON、履歴の永続化・一覧・非更新、エラー時の履歴保全を検証する。
- すべての判定は `node checks/<ID>.mjs`。`MASUME_ROOT` があればそのルートを使い、未設定なら判定ファイルの位置から解決する。`MASUME_CHARACTER` と `MASUME_NODE` によって合否や製品の挙動を変えない。
- 判定は毎回一時ディレクトリを作り、成功/失敗どちらでも削除する。子プロセスから `NODE_TEST_CONTEXT` と `NODE_OPTIONS` を外す。外部通信や外部パッケージを使用しない。
- 共有ヘルパーとフェイクも、それを読むすべてのマスの `check.seal` に含める。
- ゲートは単独入口で原因が分かった場合に `MASUME_BLAME: fortune` / `history` / `cli` を出す。結合境界だけで失敗して担当を一意に確定できない場合は関係するIDをカンマ区切りで出す。
- GMの確認時は入口がまだないため、各判定は `FAIL <ID>: 未実装: <入口>` で終了コード1となる。これは実装後も常に失敗させる仕組みではなく、入口の存在確認の後に各E2Eシナリオが続く。
