# 聞かずに決めた前提

## 根拠と優先順位

- ユーザーが明示した願いは「支出を記録して月ごとに集計するアプリ」である。
- 今回の依頼書が、この冒険の作成範囲と地図形式の一次情報である。親リポジトリの `docs/RULEBOOK.md`、`docs/CONTRACTS.md` §2、`docs/GM_GUIDE.md` も読んだ。今回の依頼書が優先される。
- 利用画面、通貨、利用人数、配布方法は指定されていない。以下はユーザーの発言ではなく、GM が今回の完成範囲として決めた前提である。

## 今回の完成範囲

- 個人が自分のPCのターミナルで使う、日本語のCLIアプリとする。Node.js 20以上の標準ライブラリだけで動き、外部サービス、通信、アカウント、本番鍵、課金を必要としない。
- 通貨は日本円。支出は正の整数円で記録し、日付・金額・カテゴリ・任意のメモを持つ。月次結果には月合計・件数・カテゴリ別合計を表示する。月は利用者が明示する。現在時刻やタイムゾーンには依存しない。
- 永続化は利用者が `KAKEIBO_FILE` で指定するローカルJSONファイルとする。複数プロセスの同時書き込みは今回の対象外。毎回別プロセスから読み直せることと、不正入力・破損データによって既存の記録を上書きしないことを保証する。
- Web画面、収入、残高、予算、編集・削除、レシート解析、銀行連携、外貨、クラウド同期、認証は今回の完成条件に含めない。
- 人間にしかできない契約・鍵の提供・審査・承認は、このローカルCLIには発生しない。依頼書の条件に従い、人間の道や形式的な承認マスは追加しない。

## あがりの一場面

利用者がCLIから9月と10月の支出を登録し、別プロセスで同じ保存先を開き直す。10月の合計とカテゴリ別内訳が10月分だけで一致し、9月分と記録のない月も正しく確認でき、不正な追加で既存の記録が変わらない。

## 実装順と判定

- 倉庫番 `store`、算術師 `tally`、案内人 `cli` の3人が、互いの実装なしで最初のタスクを始める。
- 保存と集計が初めてつながる場所は `G1`。CLIは固定応答の判定用フェイクで独立して準備し、実モジュールとの初結合は全員が集まる `GOAL` とする。
- `CONTRACTS.md` を入口・データ・エラーのSSoT、`quest.map.json` を作業順序と縄張りのSSoTとする。判定とその共通ヘルパー・フェイクはすべて `check.seal` に列挙する。
- 判定はCLIの子プロセスを起動して標準入出力と一時ファイルを検査する。アプリ内部を import しない。ソケットも外部ネットワークも不要である。
- 判定は一時ディレクトリを作成して終了時に削除する。実行時間と出力量を制限し、ゲートでは責任を特定できる段階で `MASUME_BLAME` を出す。
- GMが作るのは地図・契約・判定だけである。冒険の書作成と封印は、この依頼書の呼び出し元が後で行う。
