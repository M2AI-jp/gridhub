# 家計簿の契約

この文書は今回の家計簿のモジュール間契約のSSoTである。依頼書に基づいてGMが決めた前提は `ASSUMPTIONS.md` にある。実装担当は現在のマスと自分の縄張りだけを変更する。契約の変更はGMに依頼する。

## 1. 担当と共通実行規約

| ID | 担当 | 縄張り | 公開CLI |
| --- | --- | --- | --- |
| store | 倉庫番：保存と入力検証 | `src/store/**` | `node src/store/cli.mjs add` / `list` |
| tally | 算術師：月別集計 | `src/tally/**` | `node src/tally/cli.mjs month YYYY-MM` |
| cli | 案内人：利用者のコマンド | `src/cli/**` | `node src/cli/main.mjs …` |

GMが `quest.map.json`、`CONTRACTS.md`、`ASSUMPTIONS.md`、`checks/**` を所有する。これらは誰の縄張りにも含めない。実装は `.mjs` を用い、設定ファイルや外部パッケージを追加せず、Node.js 20以上の標準ライブラリのみを使う。

すべてのコマンドはルートから実行可能とする。成功時は終了コード0、標準出力はJSONオブジェクト1個と任意の末尾改行のみ、標準エラーは空。例外は利用者向け `--help` の日本語テキストである。失敗時は標準出力を空にし、標準エラーに `[E_コード] 日本語の説明` を1行出す。スタックトレースは不要。未知のコマンド・引数・オプション・欠落・重複オプションは `E_USAGE` / 終了2。

CLIは同期的な1回の処理で終了し、サーバーや常駐プロセスを起動しない。判定は `process.execPath` で子プロセスを起動する。内部の関数やファイル分割は自由である。判定環境の検出や固定回答による合格は認めない。

## 2. 支出の形式

追加入力は `{ "date": "2026-10-01", "amount": 1200, "category": "食費", "note": "昼食" }`。

- `date` は厳密な `YYYY-MM-DD`。年は0001〜9999、月日とうるう年はグレゴリオ暦の実在日とする。自動的な翌月への繰り上げやタイムゾーン変換をしない。
- `amount` はJSON数値で、1〜1,000,000,000の整数円。数値文字列、0、負数、小数は不正。
- `category` は文字列を `trim()` した後、Unicodeコードポイントで1〜40文字。保存値はtrim後の値とする。
- `note` は省略時 `""`。指定時は文字列、Unicodeコードポイントで0〜200文字。空白や改行を含め、値を変えず保存する。
- 追加入力の未知フィールドは `E_INPUT`。`id` は利用者から指定しない。
- 保存済み支出は上記4フィールドに `id` を加えたもの。`id` は `/^[A-Za-z0-9_-]{1,80}$/` を満たす不透明な文字列で、同じ台帳内で一意。生成方法は自由。保存済みレコードに欠落や余分なフィールドは許可しない。保存済みカテゴリは既にtrim済みでなければならない。

## 3. 倉庫番の入口と永続化

環境変数 `KAKEIBO_FILE` は台帳JSONの絶対パスで、必須。未指定は `E_CONFIG` / 終了2。今回の判定では親ディレクトリが存在する書き込み可能な一時パスを渡す。

### add

`node src/store/cli.mjs add` は標準入力のJSONオブジェクト1個を読み、§2を検証する。成功時は支出に新しいIDを付け、既存レコードの末尾に追加して永続化し、`{ "expense": <保存した支出> }` を出力する。再度同じ内容を追加しても別の支出として新IDを発行する。入力やJSON構文の誤りは `E_INPUT` / 終了2で、既存のファイルを変更しない。

### list

`node src/store/cli.mjs list` は `{ "expenses": [<保存した順の支出>] }` を出力する。標準入力は使わない。存在しない台帳は空として扱い、読み取りだけではファイルを作らない。

### ファイル

UTF-8のJSONで `{ "version": 1, "expenses": [...] }` を保存する。この2フィールド以外は許可しない。JSONのインデントと末尾改行は自由。`add` 後に終了し、別プロセスの `list` が全レコードとIDを同じ値で取得できること。

不正なJSON、未対応version、不正レコード、ID重複を含む既存ファイルは `E_STORE` / 終了1。`list` も `add` も破損を黙って空に戻さず、元ファイルをバイト単位で変更しない。読み書きのOSエラーも `E_STORE` / 終了1。失敗を成功として報告しない。同時書き込みの競合制御・クラッシュ耐性は今回の合格条件に含めない。

## 4. 算術師の入口と月次結果

`node src/tally/cli.mjs month YYYY-MM` は標準入力の `{ "expenses": [...] }` を読む。他のフィールドは許可しない。支出配列は§2の保存済み形式で、全件を検証する（対象外の月の不正レコードも拒否）。台帳ファイルを直接開かず、`KAKEIBO_FILE` を必要としない。

月は厳密な `YYYY-MM`、年0001〜9999、月01〜12。引数の形・月の不正は `E_USAGE` / 終了2。入力JSON・レコード・ID重複の不正は `E_INPUT` / 終了2。

結果の例:

```json
{
  "month": "2026-10",
  "currency": "JPY",
  "count": 3,
  "total": 1700,
  "byCategory": [
    { "category": "交通費", "count": 1, "total": 300 },
    { "category": "食費", "count": 2, "total": 1400 }
  ]
}
```

日付の先頭7文字が月に一致した支出だけを数える。`count` は件数、`total` は整数円の合計。カテゴリ配列には該当月に存在するカテゴリだけを入れ、カテゴリ文字列のJavaScript既定の辞書順（UTF-16コード単位順、locale非依存）で昇順にする。カテゴリ名 `__proto__` なども普通の文字列として集計する。

空の月は `count: 0, total: 0, byCategory: []`。入力順を変えても同じ結果になる。合計を32ビット整数に丸めず、JavaScriptの安全な整数として計算する。扱う全支出の各金額上限は§2のとおり。判定は現実的な件数で合計が32ビットを超える場合まで検査する。

## 5. 案内人の利用者向けCLI

### ヘルプと引数

`node src/cli/main.mjs --help` は終了0、日本語のヘルプを標準出力に返す。`add`・`list`・`summary`・`--date`・`--amount`・`--category`・`--note`・`--month`・`KAKEIBO_FILE` を含める。台帳や他モジュールを必要としない。

無引数、未知のコマンド、余分な位置引数、未知または重複オプション、必須オプションの欠落は `E_USAGE` / 終了2。引数解析は他モジュールを起動する前に行う。

### 記録と一覧

```sh
KAKEIBO_FILE=/absolute/ledger.json node src/cli/main.mjs add --date 2026-10-01 --amount 1200 --category 食費 --note 昼食
KAKEIBO_FILE=/absolute/ledger.json node src/cli/main.mjs list
```

`add` の必須オプションは `--date`・`--amount`・`--category`。任意の `--note` は省略時 `""`。オプション順序は自由。金額のCLI表記は `/^[1-9][0-9]*$/` を満たし、1〜1,000,000,000であること。日付とカテゴリとメモは§2の規則に従う。値の不正は `E_INPUT` / 終了2で、バックエンドを起動しない。

`add` は倉庫番の `add` にJSONを標準入力で渡し、`list` は倉庫番の `list` を呼ぶ。成功時のJSONは§3と同じ内容を返す。

### 月次集計

```sh
KAKEIBO_FILE=/absolute/ledger.json node src/cli/main.mjs summary --month 2026-10
```

月指定は必須で§4と同じ規則。不正な月は `E_USAGE` / 終了2で、バックエンドを起動しない。倉庫番の `list` のJSONを、算術師の `month 2026-10` の標準入力に渡し、§4と同じJSONを返す。別月のレコードをCLI側で事前に除外しない。空の月も算術師に渡す。

### 接続先とエラー

通常の接続先は、このアプリ自身の `src/store/cli.mjs` と `src/tally/cli.mjs`。呼び出し元のcwdではなく `main.mjs` の位置から解決する。`KAKEIBO_STORE_CLI`・`KAKEIBO_TALLY_CLI` があれば、対応する絶対パスの `.mjs` に差し替える。これらは契約検証や代替バックエンドのための正式な入口である。

子プロセスはNode実行ファイルと引数配列で起動し、シェルで文字列を評価しない。`KAKEIBO_FILE` を引き継ぐ。バックエンドの失敗は、その終了コードと標準エラーの1行を利用者へ返し、成功JSONを出さない。バックエンドが成功終了したのにJSONを返さない場合や起動できない場合は `E_BACKEND` / 終了1。モジュールの実装をコピーしてCLIだけで保存・集計を完結させない。

## 6. マスごとの範囲と結合

| マス | 担当が今回完成させる範囲 | 独立した判定の入口 |
| --- | --- | --- |
| S1 | 正常な追加・一覧・プロセスを越える保存 | 倉庫番の `add` / `list`、台帳JSON |
| S2 | 追加入力の拒否と非破壊性 | 倉庫番の `add` / `list`、台帳の前後比較 |
| T1 | 正常な月合計・カテゴリ別合計 | 算術師の `month`、標準入力に判定が用意する支出 |
| T2 | 月・入力JSON・レコードの検証 | 算術師の `month` と不正入力 |
| G1 | 保存した支出を集計へ渡す初結合 | 実storeの `list` → 実tallyの `month` |
| S3 | 破損した既存台帳を守る | 倉庫番の `add` / `list`、判定が作る破損ファイル |
| T3 | 空月・年境界・うるう日・大きな合計・入力順 | 算術師の `month` |
| C1 | 日本語ヘルプ・引数と値の検証 | 案内人の公開CLI。依存モジュール不要 |
| C2 | 追加・一覧と保存エラーの中継 | 案内人の公開CLI＋固定応答の偽store |
| C3 | 月次の接続と集計エラーの中継 | 案内人の公開CLI＋固定応答の偽store/偽tally |
| GOAL | 利用者の支出記録から月次確認まで | 実CLI → 実store / 実tally、台帳JSON |

フェイクは判定用の固定応答と呼び出し記録だけを行い、家計簿の保存・集計機能を実装しない。各担当はG1/GOALまで他担当の成果を待たず、契約だけで作業する。ゲートは責任を識別できる段階で担当IDを報告し、識別できない結合不一致を一人の責任と断定しない。
