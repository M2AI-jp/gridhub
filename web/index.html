あそびかた

GridHub は、ソフトウェアづくりをそのまま RPG すごろくにしたゲームです。道の上のマス1つ ＝ テスト1件 ＝ モンスター1体。テストが通るとモンスターを倒して、駒が1マス進みます。駒（キャラクター）は、作るものの部品を1つずつ受け持つ AI エージェント、または人間です。

1. 指令書を読む

キャラクターは、まず自分の指令書を読みます。いまいるダンジョン・いま戦うモンスター・先代から受け継いだ技・前の自分の日誌が書いてあります。

2. 1マスずつ歩く

いちばん手前のモンスター（落ちているテスト）だけを倒して、歩くで確かめます。何度でも、罰はありません。倒したモンスターには赤い斜線がつきます。

3. 出口で宣言判定

モンスターを全部倒したら、ダンジョンの出口で宣言判定。町を出てからここまでの戦いをまとめて確かめる、一発勝負です。通れば赤ペンのはなまる。

4. 負けたら町から

宣言判定に落ちると全滅。レベルが1つ下がり、最後の町からやり直しです。あいだのはなまるは消しゴムで消され、書いたものも町でセーブしたところまで戻ります（戻す前の変更は墓に残るので、なくなりません）。

5. 町でセーブ

町に着くと、宿屋に泊まってセーブします。看板にセーブの印（commit a1b2c3d）が書かれます。こまめにセーブするほど、負けたときに失うものが小さくなります。

6. 中ボスの砦

道が合流する城壁です。仲間が全員そろうとボス戦（結合ゲートの判定）が始まります。ボスの体力はテストの数。負けると、責任のある仲間だけが町へ戻されます。

7. 王様の城

人間が決めるべきところは、人間のハンコで進みます。契約・鍵・デザインの承認など、人にしかできないことだけです。

8. 冒険の書

起きたことはすべて冒険の書（追記だけのセーブデータ）に残ります。判定のファイルは GM が封印していて、書き換えると「封印が破れた」と記録されます。冒険の書が壊れると「呪われています」と出ます。盤面の時点は見出しの記録の番号（seq 42）で指し、gridhub load 42 でその時点に戻れます。

積み上げ

  • 復活: 一度倒したモンスターが、あとの変更でよみがえることがあります（赤い丸）。もう一度倒しましょう。
  • 強敵と技: 2回以上負けたモンスターを倒すと「強敵を倒した」。その直後に書いた日誌が技になり、次の代（次の出撃）に受け継がれます。
  • ちいさなメダル ◎: ダンジョンの出口を一発で抜けた数。モンスター図鑑: 計画したテストのうち、いま倒している数。
  • 作戦: いのちだいじに / バッチリがんばれ / ガンガンいこうぜ。エージェントの動き方が変わります（ルールは変わりません）。

右上の「⌨ 開発のことば」を押すと、この説明も盤面も、開発の言い方（テスト・タスク・コミット）に切り替わります。くわしいルールは docs/RULEBOOK.md。

使い方

GridHub は、E2E テストを1件ずつ通して開発を進める進行管理ボードです。道の上のマス1つ ＝ テスト1件。テストが通ると駒が1マス進みます。駒（キャラクター）はモジュールを1つずつ担当する AI エージェント（Claude Code・Codex）か人間で、担当ごとに道が分かれ、結合テストで合流します。

1. 指示を読む（brief）

gridhub brief <ID> に、いまのタスク・テスト1件ずつの成否・次に通すテスト・判定コマンド・前回までのメモと引き継ぎが出ます。コンテキストが切れても、ここから再開できます。

2. テストを1件ずつ通す（step）

最初に落ちているテストだけを通すように1か所変えて、gridhub step <ID>。いまのタスクの判定だけを走らせ、成否を記録します。何度でも、レベルも位置も変わりません。

3. 判定する（check）

全部通ったら gridhub check <ID>。直前のセーブポイントから今までの判定を累積で走らせる一発勝負です。自己申告では1マスも進みません。合格すると経験値（タスク 1 / 結合 3）。

4. 失敗したら

判定に落ちると Lv−1。直前のセーブポイントの次まで戻り、あいだのタスクは要再検証（消しゴム）になります。担当ファイルは町のコミットに git checkout され、戻す前の変更は git stash（墓）に残ります。

5. 町 = git commit

町に着くと、その担当のファイルだけが自動でコミットされます（push はしません）。看板に commit a1b2c3d。町が近いほど、失敗時に失う変更が小さくなります。

6. 結合ゲート

複数の道に同じ ID で現れるマスです。メンバーが全員そろうと結合テストが自動で走ります。失敗時は出力の MASUME_BLAME: <id> で責任のある担当だけが戻されます（無ければ全員）。

7. 承認（stamp）

check.kind: "stamp" のマスは、指定された人間のハンコで通ります。契約・本番鍵・デザイン承認など、人間が決めるべきことだけに使います。

8. 冒険の書（セーブデータ）

すべてのイベントは .masume/log.jsonl に追記され、各行が前の行のハッシュを含みます（ハッシュの鎖）。判定ファイルは GM が封印（ハッシュを記録）し、変更すると判定できません。改ざんは gridhub verify で見つかり、gridhub repair で直せます。時点は記録の番号（seq 42）と Git のコミットで指し、gridhub load <seq|commit> でその時点の盤面に戻れます。

積み上げ

  • リグレッション: 前に通ったテストが落ちると、マスに赤い丸がつきます（累積判定で必ず見つかります）。
  • 苦戦と引き継ぎ: 2回以上失敗したテストを通した直後のメモは引き継ぎ（技）として、次の起動の指示に必ず入ります。
  • 最初の判定で合格 ◎: タスクの判定を一発で通した数。テスト一覧: 計画したテストのうち、いま通っている数。
  • 作戦（--tactic）: careful / balanced / bold。エージェントが1回の起動でどこまで進むかが変わります（判定の重さは同じ）。

右上の「🗡 冒険のことば」を押すと、ゲームの言い方（モンスター・ダンジョン・町）に切り替わります。くわしくは docs/RULEBOOK.md・docs/CONTRACTS.md。CLI は gridhub（masume も同じ）。
